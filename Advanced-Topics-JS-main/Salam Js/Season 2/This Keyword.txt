Now,see,how this behaves inside global space
console.log(this);//it prints a window object

Why the value of this is window object?
let me tell you very important point

"this keyword in global space,will always have the value of global object"

so `this` keyword in global space represents the global object. Now the question is what is global object? The answer is Js does not run only in browsers,it runs in nodejs,in smart watches,in your smart phones,anywhere where Js is running,it have its own global object.Every Js platform has different global object.For example global object avaiable in browsers is different to global object in nodejs.

Whatever the global object is,`this` keyword always represents it. Now,in case of browsers,the global object is windows thats why in upper console,you see window object.but in nodejs,the value of global object is global.So,every js runtime has different value of global object.

So,if your interviewer ask about what is the value of `this` in global space?You should answer that value of `this` in global space is global object which can be different in different platforms.

}

the value of this in function is again window.In global space of browsers,it was also a window.Is both are same or different?

The answer is both are different.Inside a function,
This keyword works differently in strict mode as well as in non strict mode
Strict mode has some strict rules in js.By using "use strict" keyword on the top of the program,u will gone in strict mode.

In strict mode,the value of `this` in function is undefined while in non strict mode,it was a window

"use strict"
function data(){
console.log(this)  //undefined
}
data();
 
IMPORTANT:
The value of `this` inside a function depends on strict/non strict mode.In strict mode,the value of `this` in function is undefined while in non strict mode,it was a window. 

Why this is happened?Why `this` keyword is behaved differently in non strict mode?
This happening is due to the `this substitution` phenomenon/process. According to `this substitution`,If the value of `this` keyword is undefined or null,`this` value will be replaced with global object by JS ONLY IN NON STRICT MODE.

So,if the interviewer will asks you what is the value of this keyword inside a function?
You should say the value of `this` keyword inside a function is undefined but because JS have something known as `this substitution` process,this process replace undefined with global object in non strict mode.


In strict mode,as we discussed,in normal calling function,its value is undefined

"use strict"
function data(){
console.log(this)  //undefined
}
data();

while if we call data function with window keyword,then it will be a window object

"use strict"
function data(){
console.log(this)  //window object
}
window.data();

So we can say that value of `this` keyword depends on how the function is called

Why this is happening that calling function with window keyword,`this` value is window object while when calling without reference,it gives undefined.

The answer is when you call it without any reference then it is undefined but if you call it with window keyword,its value is window object.The reason is In JavaScript, when you define a function , it belongs to the global context, which in browser environments is the window object. Inside the data function, this refers to the object that the function is called on, which in this case is window.
So, this inside the data function refers to the window object, and when you log it, you see the window object logged to the console.

   Apply Method:

   Bind Method:
The only difference btw call and bind method is instead of directly calling the method over here,the bind method binds the method(printName) with object(student/student2) and returns the copy of function to us which will be invoked/called later .The main difference is call/apply directly  called(jesy he hum .call/.apply likhty ha tu function khud ba khud call hu jata ha) while bind give us the copy of function which will be called later.

What is the value of this in callback function of items.map?
The answer is as we know,value of this in function is determine by how the function is called,now this function is called as a callback function,not called by an object thats why now this is pointing to window object.
Similarly in below example

    console.log(this);  
    
   }
   another() //hum khud isy call kr rhy ha thats why the value of this is window object
  }

Now the question is how to access the value of this in callback function of items.map,the answer is use arrow function
let obj={
  name:'usman',
  items:['a','b','c'],
  show:function(){
    this.items.map((data)=>{
      console.log(this.name,' is ',data); //now this pointing to object
      
    })
  }
}
console.log(obj.show()); 


Now if anyone says , use this in regular function without arrow function,Remember this should be point out to object,not on window,how can you do this

There are two ways

1-Assign this to variable 
let obj={
  name:'usman',
  items:['a','b','c'],
  show:function(){
    let self=this;
    this.items.map(function(data){
      console.log(self.name,' is ',data);
      
    })
  }
}
console.log(obj.show());

2-bind(this)

By using bind(this), you force the callback’s this to always equal the this of show (which is obj).
let obj={
  name:'usman',
  items:['a','b','c'],
  show:function(){
    this.items.map(function(data){
      console.log(this.name,' is ',data);
      
    }.bind(this))
  }
}
console.log(obj.show());
