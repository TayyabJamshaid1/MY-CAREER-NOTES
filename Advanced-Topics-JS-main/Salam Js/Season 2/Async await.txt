ASYNC

Async is a keyboard that is used before a function to create a async function.

This is  a async function
async function getData(){

}

=>ASYNC FUNCTION ALLWAYS RETURNS A PROMISE
There are 2 cases in this scenario

a)You can return a value(string/number/object/array/boolean).In case of values,js automatically take this value and wrap it in a promise and will return that wrap promise.For example,
async function getData(){
return "Tayyab"; //wrapped in promsise and then return it
}

const data=getData();
console.log(data);

[[Prototype]]:Promise
[[PromiseState]]: "fulfilled"
[[PromiseResult]]: "Tayyab"

Now,what happens is we have got this promise inside this getData.Now how could we get our actual data from this promise?

We can use a .then method
data.then((data)=>{console.log(data)}) //Tayyab

So,in any case,we conclude that async function always returns a promise in any situation

b)You can return a promise in async function
if are returning value is already a promise in async function,then it will not wrapped in any other promise.It will return as it is.For example,

let p =new Promise((resolve,reject)=>{
  resolve("KESA")
})
async function getData(){
  return p;//return the promise as it is
  }
  
  const data=getData();
  data.then((data)=>{console.log(data)}) //KESA  

  Using Await with async

Await is a keyword that can only be used inside a async function
Async and await combo(together) is used to handle promises
Await resolve the promise

Why we need async await?
Let me show you  before async await,how do we handle promises
learn it by example

Why both the data displayed together?
Because initially in our call stack,it first executes the promise here.While executing,it checks that setTimeout is here,so js engine moved the setTimeout in webapi and removed it from call stack.After that it called the getData function,getData function is in call stack,remember that settimeout timer  in webapi is still running.Now in getData, when it reaches on first await,it suspends the execution of getData,removed it from call stack,getData is now in webapi,isi drmayan timer b complete hu gya ha,after completion of timer,setTimeout callback function moves in callback quene,event loop us callback function ko call stack me push kr dta ha jis sy hamara promise resolve hu jata ha. After promise resolved,webapi moved getData in callback quene,eventloop take it from callback quene and moved the  getData into call stack again ,it executes the console statement and show resolve value.Then it moved on second await,again its execution suspends,it moved in webapi,ab kyu k p already resolve hu gya ha,is lye foran he webapi isy callback quene me bhjy gi aur eventloop kyu k callstack abi empty ha,is lye foran he isy callstack me push kr dy ga,phr jaha sy isny program chora tha waha sy continue kary ga,then js engine print its console and data.Kyu k promise phly sy he resolve tha,is lye foran he dosry ka data b show hu gya micro mini seconds mei

REMEMBER:
In case of 2 awaits in one function,Ek await k bad jab dobara function call stack me execute huny k lye ata ha,function again start sy continue krny ki bjaiy wahi sy he continue krta ha jaha sy wo chor k gya tha

What is fetch?
Fetch function is basically a promise.When this promise is resolved,it gives you a Response object(a readable stream).Suppose,u have to convert this readable stream in json,u can do it like Response.json(). This Response.json() is again a promise and when this promise is resolved,it gave us results

}

  throw new Error("Async error");

try {
  asyncFn();
} catch (e) {
  console.log("Caught:", e.message);
}

console.log("After async error");

//suggestion to Caught error:
// Option 1: Using await in another async function
(async () => {
  try {
    await asyncFn();
  } catch (e) {
    console.log("Caught:", e.message);
  }
})();

// Option 2: Using .catch()
asyncFn().catch(e => {
  console.log("Caught:", e.message);
});

imp Point:
.resolve() schedules .then() as a microtask,
but does not call it immediately —
it waits until the current synchronous code (GEC) finishes.

--
When you throw inside a .then() handler, it automatically rejects the promise with the thrown value as the rejection reason.The throw causes the Promise chain to skip any subsequent .then() handlers and jump directly to the nearest .catch() handler.
