As see in picture(part 1) in settimeout folder,let suppose we have 1000 of consoles/lengthy code,it start executing in main thread(call stack) line by line,in that code we also have setTimeOut with 5 seconds.So when the code is executing,setTimeout will go in web apis and their timer starts.Remember our code is still executing and it will take more time to execute all the code.In between this,our setTimeOut timer has been ended,it moves in callback quene and now event loop is waiting that when gec removed,it will push that sitTimeOut function in call stack.So here is the problem that setTimeout timer is end but it still waits for execution until gec pop out from main thread. This is also known as "Concurrency model of JS".

Settimeout does not guarantee that it will do our task exactly after given time but yes it gurantee that it will wait atleast given time or may be any time after that.
